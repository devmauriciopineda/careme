# UC-008 — Gestionar información clínica ausente

## 1. Identificación

| Campo           | Valor                                                              |
| --------------- | ------------------------------------------------------------------ |
| ID              | UC-008                                                             |
| Nombre          | Gestionar información clínica ausente                              |
| Actor principal | Persona que consulta su historia clínica                           |
| Nivel           | Objetivo de usuario                                                |
| Sistema         | Careme — asistente de historia clínica personal                    |
| Prioridad       | Alta — protege la confianza en el asistente: es preferible una negativa clara a una respuesta inventada |
| Estado          | Propuesto                                                          |

## 2. Objetivo

Que el usuario reciba una respuesta explícita, comprensible y accionable cuando
pregunta por información clínica que su historia no respalda, de modo que sepa
con certeza que no hay registros y qué puede hacer al respecto, sin que el
sistema rellene el vacío con suposiciones.

## 3. Precondiciones

- El sistema está disponible.
- El usuario tiene acceso al chat del asistente, que es el punto de entrada del
  producto.
- Existe una sola historia clínica: la del propio usuario.
- El usuario ha planteado una pregunta que **sí** pretende consultar su historia
  clínica; no se trata de una pregunta de carácter general.
- La historia clínica puede estar completamente vacía o contener hechos que no
  responden a la pregunta; ambos casos son válidos.

## 4. Disparador

El sistema, tras buscar en la historia los hechos que podrían responder la
pregunta, no encuentra ningún hecho que la respalde.

## 5. Flujo principal

1. El usuario plantea una pregunta sobre su propia historia clínica.
2. El sistema reconoce que la pregunta pretende consultar la historia y busca en
   ella los hechos que podrían responderla.
3. El sistema no encuentra ningún hecho que responda la pregunta.
4. El sistema declara de forma explícita que no encuentra registros que
   respalden lo preguntado, sin presentar ninguna afirmación como si estuviera
   respaldada.
5. El sistema indica al usuario que la ausencia de registros no significa que el
   hecho no haya ocurrido, sino que no consta en su historia.
6. El sistema ofrece una salida útil: que el usuario reformule la pregunta o
   registre el hecho si lo recuerda y no consta.
7. **Resultado:** el usuario sabe que su historia no contiene información que
   responda la pregunta, entiende qué significa esa ausencia y dispone de un
   camino para continuar.

## 6. Flujos alternos y excepciones

| Código | Situación                                                                                       | Respuesta del sistema                                                                                                                                    |
| ------ | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1     | La historia clínica está completamente vacía: no hay ningún hecho registrado                     | El sistema declara que todavía no hay registros en la historia y lo presenta como el estado inicial esperable, no como un error.                           |
| A2     | La pregunta busca un hecho de un tipo que el usuario nunca ha registrado ("¿qué medicación tomo?") | El sistema declara que no encuentra registros de ese tipo de hecho y no deduce la respuesta de otros hechos.                                              |
| A3     | La pregunta busca un hecho en un periodo concreto sin resultados ("¿qué me pasó el año pasado?")  | El sistema declara que no encuentra registros en ese periodo y aclara que la ausencia se refiere a ese periodo, no a toda la historia.                     |
| A4     | La pregunta usa palabras que no coinciden con las del registro, aunque el hecho exista             | El sistema declara que no encuentra registros con esos términos y ofrece reformular la pregunta con otras palabras.                                        |
| A5     | Parte de la pregunta puede responderse y parte no                                                      | El sistema responde solo con lo que sí está respaldado, declara explícitamente qué parte no tiene registros y no completa la parte ausente con suposiciones. |
| A6     | El usuario insiste en la misma pregunta tras la negativa                                         | El sistema mantiene la misma declaración sin ceder a la insistencia y sin fabricar una respuesta para complacer al usuario.                                |
| A7     | La pregunta es en realidad de carácter general y nunca pretendió consultar la historia           | El sistema no declara una ausencia de registros y atiende la pregunta como conversación general (ver UC-010).                                            |
| E1     | El sistema no puede completar la búsqueda en la historia y por tanto no puede afirmar si hay registros | El sistema informa del fallo en el idioma del usuario, sin mostrar detalles internos, y no declara una ausencia que no ha podido comprobar.                |

## 7. Postcondiciones

- **Éxito (feliz, A1, A2, A3, A4):** el usuario recibe una declaración explícita
  de que no hay registros que respondan la pregunta; ninguna afirmación se
  presenta como respaldada; la historia clínica permanece exactamente como
  estaba.
- **A5:** el usuario recibe una respuesta parcialmente respaldada, con la parte
  ausente declarada de forma explícita; la historia clínica no se modifica.
- **A6:** el usuario recibe la misma declaración de ausencia que en el primer
  intento; no se añade ninguna afirmación no respaldada; la historia clínica no
  se modifica.
- **A7:** no se declara una ausencia de registros porque no procedía buscar; la
  consulta se atiende como conversación general y la historia permanece sin
  cambios.
- **Fallo (E1):** el usuario recibe un aviso de fallo y **no** una afirmación de
  ausencia; la historia permanece exactamente como estaba y la pregunta puede
  repetirse.

## 8. Reglas de negocio

- La ausencia de registros se declara siempre de forma explícita; nunca se
  responde al vacío con silencio ni con una respuesta aparente.
- El sistema no completa la información ausente con conocimiento general,
  suposiciones ni inferencias a partir de otros hechos.
- La ausencia de registros se refiere a lo que consta en la historia, no a lo
  que haya ocurrido en la vida del usuario; la respuesta no afirma ni niega que
  el hecho haya sucedido.
- El sistema no deduce hechos no registrados a partir de hechos sí registrados.
- Ante la insistencia del usuario, la declaración de ausencia se mantiene sin
  cambios; no se fabrica información para satisfacer la petición.
- Una búsqueda que no pudo completarse no es una ausencia de registros: son
  situaciones distintas y se comunican de forma distinta.
- Cuando la pregunta es de carácter general y no pretendía consultar la historia,
  no se declara ninguna ausencia de registros.
- La declaración de ausencia no expone detalles internos del sistema ni
  describe cómo se realiza la búsqueda.
- La historia clínica no se modifica en ningún caso de este caso de uso.
- Siempre que la situación lo permita, el sistema ofrece al usuario un camino
  para continuar: reformular la pregunta o registrar el hecho que no consta.

## 9. Requisitos no funcionales relevantes

- **Claridad absoluta:** el usuario no debe poder confundir una ausencia de
  registros con una respuesta ni con un error del sistema.
- **No invención:** ninguna afirmación se presenta como respaldada cuando no lo
  está.
- **No inducción a error clínico:** la respuesta no debe poder interpretarse como
  que el hecho no ocurrió, solo como que no consta.
- **Accionabilidad:** tras la negativa, el usuario sabe qué puede hacer a
  continuación.
- **Resiliencia:** ante un fallo de búsqueda, el usuario conserva su pregunta y
  puede volver a intentarlo.
- **Distinción de estados:** la ausencia de registros, el fallo y la respuesta
  fundamentada se perciben como resultados distintos e inconfundibles.
- **Lenguaje comprensible:** la declaración usa el lenguaje del usuario y no
  expone detalles internos del sistema.
- **Idioma:** los textos visibles para el usuario están en español.

## 10. Fuera de alcance

- Responder preguntas que sí están respaldadas por registros (UC-007).
- Responder preguntas de carácter general que no consultan la historia (UC-010).
- Registrar el hecho que el usuario echa en falta (UC-004); este caso de uso
  puede ofrecerlo como salida, pero no lo ejecuta.
- Corregir, completar, editar o borrar hechos ya registrados.
- Completar la historia con información obtenida de otras fuentes.
- Buscar por significado cuando las palabras del usuario no coinciden con las
  del registro (búsqueda semántica).
- Inspeccionar técnicamente los hechos almacenados (UC-011).
- Recomendaciones médicas, diagnósticos o interpretación clínica.
- Consultar el peso y la circunferencia abdominal, que tienen su propio
  seguimiento.
- Múltiples pacientes, cuentas, roles o acceso de terceros.

## 11. Frontera con UC-007 y UC-010

Los tres casos de uso describen respuestas del asistente dentro del mismo chat y
comparten precondiciones, actor y disparador genérico. Se distinguen por lo
siguiente:

| Criterio                                     | UC-007                                | UC-008                                | UC-010                                  |
| -------------------------------------------- | ------------------------------------- | ------------------------------------- | --------------------------------------- |
| ¿La pregunta pretende consultar la historia? | Sí                                    | Sí                                    | No                                      |
| ¿La historia contiene hechos de apoyo?       | Sí                                    | No                                    | No procede buscar                       |
| Resultado observable para el usuario         | Respuesta fundada con sus referencias | Declaración explícita de ausencia     | Respuesta conversacional general        |
| Relación entre los casos                     | Flujo principal de la consulta        | Desenlace posible de UC-007 (`A8`)    | Desenlace posible de UC-007 (`A7`)      |

- **UC-007 vs UC-008:** UC-007 trata la ausencia de registros como una variación
  de la consulta; UC-008 la desarrolla como objetivo propio, con las
  consecuencias de comunicar correctamente una negativa. UC-008 se ocupa de la
  ausencia **habiendo buscado**; si no se encontró porque no se buscó, aplica
  UC-010.
- **UC-007 vs UC-010:** el criterio de separación es si la pregunta depende de la
  historia clínica; solo cuando depende se busca. A7 de UC-007 remite aquí.
- **UC-008 vs UC-010:** una pregunta que nunca pretendió consultar la historia no
  puede producir una ausencia de registros; son desenlaces mutuamente
  excluyentes.
- **Fallo de búsqueda:** no es una ausencia de registros ni una consulta general;
  se comunica como fallo recuperable y pertenece a las excepciones de UC-007
  (`E1`, `E3`).
