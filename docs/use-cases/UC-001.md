# UC-001 — Ver el seguimiento corporal

## 1. Identificación

| Campo           | Valor                                         |
| --------------- | --------------------------------------------- |
| ID              | UC-001                                        |
| Nombre          | Ver el seguimiento corporal                   |
| Actor principal | Persona que hace seguimiento de su cuerpo     |
| Nivel           | Objetivo de usuario                           |
| Sistema         | Careme — aplicación de seguimiento corporal   |
| Prioridad       | Alta — es la única funcionalidad del producto |
| Estado          | Implementado                                  |

## 2. Objetivo

Que el usuario conozca la evolución de las métricas corporales que tienen datos,
viéndolas como tendencias y como valores concretos por fecha, y pueda elegir
qué métricas consultar.

## 3. Precondiciones

- El sistema está disponible.
- Existen mediciones registradas (puede no haber ninguna; ver A1).
- El usuario tiene acceso a la pantalla de seguimiento.

## 4. Disparador

El usuario abre la pantalla de seguimiento corporal.

## 5. Flujo principal

1. El usuario abre la pantalla de seguimiento corporal.
2. El sistema recupera las mediciones registradas de todas las métricas del
  catálogo.
3. El sistema ordena las mediciones de la más antigua a la más reciente y
  comprueba que cada una es válida.
4. El sistema ofrece para seleccionar únicamente las métricas que tienen datos,
  seleccionando por defecto el peso y la circunferencia abdominal cuando están
  disponibles.
5. El usuario selecciona las métricas que desea consultar.
6. El sistema muestra una gráfica individual para cada métrica seleccionada,
  con su unidad de referencia.
7. El sistema muestra una única tabla con las fechas y las columnas
  correspondientes a las métricas seleccionadas.
8. **Resultado:** el usuario conoce la evolución de las métricas seleccionadas,
  tanto como tendencia como mediante sus valores por fecha.

## 6. Flujos alternos y excepciones

| Código | Situación | Respuesta del sistema |
| ------ | --------- | -------------------- |
| A1 | No hay ninguna medición registrada | El sistema informa de que aún no hay datos y muestra la pantalla vacía. |
| A2 | El usuario cambia entre la vista de tendencia y el detalle por fecha | Ambas vistas muestran la misma información para las métricas seleccionadas. |
| A3 | El usuario cambia las métricas seleccionadas | El sistema actualiza las gráficas y las columnas de la tabla para mostrar únicamente las métricas seleccionadas. |
| A4 | El usuario consulta la presión arterial | El sistema la muestra en una gráfica con dos series, una para la presión sistólica y otra para la diastólica. |
| E1 | El sistema no puede obtener las mediciones de una métrica | El sistema informa del fallo de esa métrica, permite reintentarla y mantiene disponibles las demás métricas. |

## 7. Postcondiciones

- **Éxito:** el usuario ha visto el seguimiento de las métricas seleccionadas.
  No se altera ningún dato.
- **A3:** se muestran únicamente las gráficas y columnas correspondientes a las
  métricas seleccionadas.
- **A4:** la presión arterial se muestra como una única métrica con sus dos
  series.
- **Fallo (E1):** la métrica afectada no se muestra correctamente; se informa del
  fallo y se ofrece reintentarla. Las demás métricas siguen disponibles.

## 8. Reglas de negocio

Reglas transversales aplicables —
[`reglas-de-negocio.md`](./reglas-de-negocio.md): RN-009.

Reglas propias de este caso de uso:

- Se admite como máximo una medición por día.
- **UC-001-R1:** el catálogo determina las métricas disponibles y la unidad de
  referencia de cada una; puede ampliarse con nuevas métricas.
- **UC-001-R2:** solo se ofrecen para seleccionar las métricas que tienen
  mediciones registradas.
- **UC-001-R3:** el peso y la circunferencia abdominal aparecen seleccionados
  por defecto cuando tienen mediciones registradas.
- **UC-001-R4:** cada métrica seleccionada se muestra en su propia gráfica y en
  la columna correspondiente de una única tabla.
- **UC-001-R5:** la presión arterial se presenta como una sola métrica con dos
  series: sistólica y diastólica.
- **UC-001-R6:** el orden de presentación es siempre del más antiguo al más
  reciente.

## 9. Requisitos no funcionales relevantes

- **Consistencia temporal:** la fecha de una medición debe verse igual
  independientemente de dónde se encuentre el usuario; no puede desplazarse por
  su ubicación geográfica.
- **Datos siempre al día:** lo mostrado refleja el estado del registro en el
  momento de abrir la pantalla, sin versiones antiguas guardadas.
- **Accesibilidad:** una persona que no distingue los colores debe poder saber
  qué métrica representa cada gráfica y qué serie representa cada valor; debe
  poder seleccionar métricas y recorrer los valores con el teclado; la
  información no puede depender solo de una gráfica.
- **Idioma:** los textos visibles para el usuario están en español.
- **Resiliencia:** ante un fallo al obtener los datos de una métrica, el usuario
  recibe un mensaje comprensible y puede volver a intentarlo sin perder las
  demás métricas.

## 10. Fuera de alcance

- Registrar, editar o borrar mediciones.
- Identificar al usuario o restringir el acceso.
- Distinguir mediciones de distintas personas.
- Notificaciones, objetivos o recomendaciones.
- Interpretar los valores, diagnosticar o recomendar tratamientos.
- Traducción a otros idiomas en tiempo de ejecución y modo oscuro.
