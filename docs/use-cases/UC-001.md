# UC-001 — Ver el seguimiento corporal

## 1. Identificación

| Campo           | Valor                                         |
| --------------- | --------------------------------------------- |
| ID              | UC-001                                        |
| Nombre          | Ver el seguimiento corporal                   |
| Actor principal | Persona que hace seguimiento de su cuerpo     |
| Nivel           | Objetivo de usuario                           |
| Sistema         | Careme — aplicación de seguimiento corporal   |
| Prioridad       | Alta — es la única funcionalidad del producto |
| Estado          | Implementado                                  |

## 2. Objetivo

Que el usuario conozca la evolución de su peso y de su cintura abdominal a lo
largo del tiempo, viéndolos como tendencia y como valores concretos por fecha.

## 3. Precondiciones

- El sistema está disponible.
- Existen mediciones registradas (puede no haber ninguna; ver A1).
- El usuario tiene acceso a la pantalla de seguimiento.

## 4. Disparador

El usuario abre la pantalla de seguimiento corporal.

## 5. Flujo principal

1. El usuario abre la pantalla de seguimiento corporal.
2. El sistema recupera todas las mediciones registradas.
3. El sistema las ordena de la más antigua a la más reciente y comprueba que
   cada una es válida.
4. El sistema prepara la información para presentarla como tendencia en el
   tiempo y como valores puntuales por fecha.
5. El sistema muestra la evolución del peso y de la cintura abdominal, tanto en
   forma de tendencia como de detalle por fecha.
6. **Resultado:** el usuario conoce su evolución corporal.

## 6. Flujos alternos y excepciones

| Código | Situación                                         | Respuesta del sistema                                                     |
| ------ | ------------------------------------------------- | ------------------------------------------------------------------------- |
| A1     | No hay ninguna medición registrada                | El sistema informa de que aún no hay datos y muestra la pantalla vacía.   |
| A2     | El usuario cambia entre la vista de tendencia y el detalle por fecha | Ambas vistas muestran la misma información, sin volver a consultar datos. |
| E1     | El sistema no puede obtener las mediciones        | El sistema informa del fallo en el idioma del usuario y ofrece reintentar. |

## 7. Postcondiciones

- **Éxito:** el usuario ha visto su seguimiento. No se altera ningún dato.
- **Fallo (E1):** no se muestra información; se ofrece reintentar.

## 8. Reglas de negocio

Reglas transversales aplicables —
[`reglas-de-negocio.md`](./reglas-de-negocio.md): RN-009.

Reglas propias de este caso de uso:

- Se admite como máximo una medición por día.
- Toda medición tiene una fecha, un peso en kilogramos y una cintura abdominal
  en centímetros; ambos valores son positivos y se expresan con un decimal.
- El orden de presentación es siempre del más antiguo al más reciente.

## 9. Requisitos no funcionales relevantes

- **Consistencia temporal:** la fecha de una medición debe verse igual
  independientemente de dónde se encuentre el usuario; no puede desplazarse por
  su ubicación geográfica.
- **Datos siempre al día:** lo mostrado refleja el estado del registro en el
  momento de abrir la pantalla, sin versiones antiguas guardadas.
- **Accesibilidad:** una persona que no distingue los colores debe poder saber
  qué serie es el peso y cuál la cintura; debe poder recorrer los valores con el
  teclado; la información no puede depender solo de una gráfica.
- **Idioma:** los textos visibles para el usuario están en español.
- **Resiliencia:** ante un fallo al obtener los datos, el usuario recibe un
  mensaje comprensible y puede volver a intentarlo.

## 10. Fuera de alcance

- Registrar, editar o borrar mediciones.
- Identificar al usuario o restringir el acceso.
- Distinguir mediciones de distintas personas.
- Notificaciones, objetivos o recomendaciones.
- Traducción a otros idiomas en tiempo de ejecución y modo oscuro.
