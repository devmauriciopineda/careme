# UC-003 — Cargar mediciones desde un archivo

## 1. Identificación

| Campo           | Valor                                              |
| --------------- | -------------------------------------------------- |
| ID              | UC-003                                             |
| Nombre          | Cargar mediciones desde un archivo                 |
| Actor principal | Persona que hace seguimiento de su cuerpo          |
| Nivel           | Objetivo de usuario                                |
| Sistema         | Careme — aplicación de seguimiento corporal        |
| Prioridad       | Alta — permite incorporar el histórico de una vez  |
| Estado          | Implementado                                       |

## 2. Objetivo

Que el usuario incorpore de una sola vez varias mediciones de su peso y de su
circunferencia abdominal, tomadas de un archivo que ya tiene, sin tener que
registrarlas una por una.

## 3. Precondiciones

- El sistema está disponible.
- El usuario tiene acceso a la pantalla de seguimiento corporal (UC-001).
- El usuario dispone de un archivo de mediciones con la estructura requerida.
- No se exige que existan mediciones previas.

## 4. Disparador

El usuario confirma la carga del archivo de mediciones que previamente
seleccionó.

## 5. Flujo principal

1. El usuario inicia la carga de datos desde la pantalla de seguimiento
   corporal.
2. El sistema le solicita el archivo de mediciones.
3. El usuario elige el archivo.
4. El sistema comprueba que el archivo cumple la estructura requerida y que no
   supera los límites admitidos.
5. El sistema muestra una previsualización de las mediciones contenidas,
   indicando cuáles serían nuevas y cuáles reemplazarían a un registro ya
   existente de la misma fecha.
6. El usuario confirma la carga.
7. El sistema informa de que la carga está en curso, sin interrumpir al usuario
   ni retener la pantalla.
8. El sistema comprueba de nuevo el archivo y guarda sus mediciones: crea las de
   las fechas que no tenían registro y reemplaza los valores de las fechas que
   ya lo tenían.
9. Terminada la carga, el sistema informa del resultado dentro de la pantalla de
   seguimiento, indicando cuántas mediciones se crearon y cuántas se
   reemplazaron, y deja el seguimiento al día.
10. **Resultado:** el usuario ve sus mediciones incorporadas al seguimiento
    corporal.

## 6. Flujos alternos y excepciones

| Código | Situación                                                              | Respuesta del sistema                                                                                                            |
| ------ | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| A1     | El archivo incluye una fecha sin valores de peso ni de circunferencia  | El sistema ignora esa fila sin informar de error y continúa con el resto.                                                        |
| A2     | El archivo repite una misma fecha en varias filas                     | El sistema no informa de error: la última fila de esa fecha reemplaza a las anteriores, de modo que solo se conserva una medición por día. |
| A3     | El archivo omite fechas o tiene huecos entre mediciones                | El sistema no informa de error; las fechas ausentes simplemente no se cargan y no alteran lo ya registrado.                     |
| A4     | El usuario no confirma la carga tras la previsualización               | El sistema no guarda nada y mantiene el seguimiento como estaba.                                                                 |
| E1     | El archivo no cumple la estructura requerida (falta una columna, los nombres no son los exigidos o el contenido no puede interpretarse) | El sistema aborta la carga completa, no guarda ninguna medición, explica en su idioma en qué consiste el incumplimiento y permite elegir otro archivo. |
| E2     | Alguna fila contiene un valor que no cumple las reglas de una medición | El sistema aborta la carga completa, no guarda ninguna medición, señala la fila y el motivo del rechazo, y permite elegir otro archivo. |
| E3     | El archivo supera el tamaño o el número de filas admitido              | El sistema rechaza el archivo, no guarda ninguna medición e informa del límite superado.                                          |
| E4     | El sistema no puede completar la carga                                | El sistema informa del fallo en su idioma, deja el seguimiento como estaba —sin cargas parciales— y ofrece volver a intentarlo.   |

## 7. Postcondiciones

- **Éxito:** las mediciones del archivo quedan incorporadas; existe como máximo
  una medición por día, con los valores del archivo; el seguimiento lo refleja.
- **A1, A2, A3:** las filas ignoradas no dejan rastro; las fechas repetidas
  quedan con una sola medición; los huecos del archivo no alteran lo ya
  registrado.
- **A4:** no se guarda ninguna medición.
- **Fallo (E1, E2, E3, E4):** no se guarda ninguna medición del archivo; el
  seguimiento permanece exactamente como estaba antes de la carga; el usuario
  puede volver a intentarlo con otro archivo o en otro momento.

## 8. Reglas de negocio

- El archivo debe contener exactamente las columnas de fecha, peso y
  circunferencia abdominal, con los nombres exigidos; el orden entre columnas no
  importa.
- La fecha se expresa como un día del calendario, sin hora, en el formato
  acordado, y no puede ser futura.
- Toda medición tiene una fecha, un peso en kilogramos y una circunferencia
  abdominal en centímetros; ambos valores son obligatorios, positivos y se
  expresan con un decimal.
- El peso no puede superar 500 kilogramos y la circunferencia abdominal no puede
  superar 400 centímetros.
- Se admite como máximo una medición por día: una fecha ya registrada se
  reemplaza en lugar de duplicarse.
- Las fechas ausentes o incompletas no son un error: solo se cargan las
  mediciones que el archivo contiene con sus valores.
- El archivo puede contener hasta 10000 filas y pesar hasta 10 megabytes; más
  allá de esos límites no se admite.
- La carga es de todo o nada: si alguna parte del archivo no es admisible, no se
  incorpora ninguna medición.

## 9. Requisitos no funcionales relevantes

- **Control previo:** el usuario conoce, antes de confirmar, qué mediciones se
  cargarían y cuáles reemplazarían a un registro existente.
- **Carga sin bloqueo:** el usuario ve que la carga avanza y conserva la pantalla
  que estaba consultando; el resultado aparece al terminar, sin tener que repetir
  la acción ni recargar.
- **Resultado no intrusivo:** el resultado de la carga se comunica dentro de la
  pantalla de seguimiento, sin interrumpir ni bloquear lo que el usuario esté
  haciendo.
- **Sin cargas a medias:** un archivo no admisible o un fallo no deja el
  seguimiento a medio actualizar; o quedan todas las mediciones, o ninguna.
- **Validación comprensible:** cuando el archivo no es admisible, el usuario
  recibe un mensaje claro en su idioma que explica qué corregir, sin mencionar
  detalles internos.
- **Consistencia temporal:** la fecha de cada medición se interpreta como un día
  del calendario y debe quedar igual independientemente de dónde se encuentre el
  usuario; no puede desplazarse por su ubicación geográfica.
- **Datos siempre al día:** terminada la carga, el seguimiento refleja las
  mediciones incorporadas sin que el usuario tenga que recargar ni repetir la
  acción.
- **Repetición segura:** intentar la misma carga dos veces no duplica mediciones
  para una misma fecha.
- **Accesibilidad:** la acción de carga y su resultado son alcanzables y
  comprensibles con el teclado y sin depender solo del color.
- **Idioma:** los textos visibles para el usuario están en español.

## 10. Fuera de alcance

- Descargar una plantilla del archivo ni exportar las mediciones existentes.
- Cargar datos desde otros formatos distintos del acordado (hojas de cálculo u
  otros).
- Corregir, completar o editar las mediciones dentro de la previsualización
  antes de cargarlas.
- Cargar varios archivos a la vez.
- Sincronización automática o periódica con fuentes externas.
- Editar o borrar mediciones existentes como acción independiente (el reemplazo
  ocurre únicamente al cargar la misma fecha).
- Identificar al usuario o restringir el acceso.
- Distinguir mediciones de distintas personas.
- Notificaciones, objetivos o recomendaciones.
